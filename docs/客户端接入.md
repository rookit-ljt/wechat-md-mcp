# 客户端接入

五个客户端共用同一个入口：仓库里的 `bin/md-mcp`（stdio 传输）。区别只在配置文件放哪、什么格式。

| 客户端 | 配置位置 | 格式 |
| --- | --- | --- |
| WorkBuddy | `~/.workbuddy/mcp.json` | JSON |
| Claude Desktop | `~/Library/Application Support/Claude/claude_desktop_config.json` | JSON |
| Claude Code | `~/.claude.json`，或项目根目录 `.mcp.json`，或 `claude mcp add` | JSON |
| Codex | `~/.codex/config.toml` | TOML |
| Cursor | `~/.cursor/mcp.json`（全局）或项目根目录 `.cursor/mcp.json` | JSON |

把下面的 `/path/to/wechat-md-mcp` 换成你实际的 clone 路径。

## Codex

编辑 `~/.codex/config.toml`，追加：

```toml
[mcp_servers.wechat-md-mcp]
command = "/path/to/wechat-md-mcp/bin/md-mcp"
args = []
```

Codex 启动新会话时才会加载，改完重开一个会话即可。

## Claude Desktop

编辑 `~/Library/Application Support/Claude/claude_desktop_config.json`，在 `mcpServers` 下加一项：

```json
{
  "mcpServers": {
    "wechat-md-mcp": {
      "command": "/path/to/wechat-md-mcp/bin/md-mcp",
      "args": []
    }
  }
}
```

如果文件里已经有别的 server，只加里面那一项，别整文件覆盖。

**改完必须完全退出 Claude Desktop 再重开**，配置只在冷启动时读取。JSON 有语法错误的话 Claude 会直接起不来。

成功后输入框右下角会出现锤子图标，点开能看到 5 个工具。

## Claude Code

命令行注册（推荐，不用手工编辑 JSON）：

```bash
claude mcp add wechat-md-mcp -- /path/to/wechat-md-mcp/bin/md-mcp
```

或者写成项目级配置文件 `.mcp.json`，团队可以共享：

```json
{
  "mcpServers": {
    "wechat-md-mcp": {
      "command": "/path/to/wechat-md-mcp/bin/md-mcp",
      "args": []
    }
  }
}
```

## Cursor

全局配置 `~/.cursor/mcp.json`，或项目级的 `.cursor/mcp.json`（只对该项目生效）：

```json
{
  "mcpServers": {
    "wechat-md-mcp": {
      "command": "/path/to/wechat-md-mcp/bin/md-mcp",
      "args": []
    }
  }
}
```

注意 `~/.cursor/mcp.json` 有可能被 root 占着（某次用 sudo 启动留下的），那样你自己的编辑器写不进去。先确认属主：

```bash
ls -l ~/.cursor/mcp.json
```

属主是 root 就先收回：

```bash
sudo chown "$USER" ~/.cursor/mcp.json
```

## WorkBuddy

`~/.workbuddy/mcp.json`：

```json
{
  "mcpServers": {
    "wechat-md-mcp": {
      "command": "/path/to/wechat-md-mcp/bin/md-mcp",
      "args": []
    }
  }
}
```

还需要在「连接器管理」页面右上角的自定义连接器入口里，对新服务点「信任」才会生效。

## 不想用 shell 启动器时

`bin/md-mcp` 是 macOS 上的 zsh 脚本。如果在别处遇到问题，可以直接用 node 调用同样的入口——任何有 Node 的系统都认这个形式：

```bash
node /path/to/wechat-md-mcp/node_modules/tsx/dist/cli.mjs /path/to/wechat-md-mcp/run-mcp.mjs
```

配到 Claude Desktop 就是：

```json
{
  "mcpServers": {
    "wechat-md-mcp": {
      "command": "node",
      "args": [
        "/path/to/wechat-md-mcp/node_modules/tsx/dist/cli.mjs",
        "/path/to/wechat-md-mcp/run-mcp.mjs"
      ]
    }
  }
}
```

代价是丢掉启动器做的两件事（清 `NODE_OPTIONS`、自动找 Node），见下一节。

## 装 Skill（建议一起做）

MCP 只提供「能调的工具」，不会告诉 agent 什么时候该用、按什么顺序用、哪些坑不能踩。`skills/wechat-md/SKILL.md` 补的就是这一层。

SKILL.md 是这几家 agent 通用的格式，装法是**同一份文件，各家目录各放一条软链**：

```bash
SKILL=/path/to/wechat-md-mcp/skills/wechat-md
ln -s "$SKILL" ~/.claude/skills/wechat-md
ln -s "$SKILL" ~/.codex/skills/wechat-md
ln -s "$SKILL" ~/.cursor/skills/wechat-md
ln -s "$SKILL" ~/.workbuddy/skills/wechat-md
```

用软链而不是复制，是为了改一份就四家同时生效。

装完之后，跟任意一家说「把这篇文章排版成公众号格式」，它会自己去找 `.editor-state.json` 里的品牌配置、渲染、然后复制进剪贴板，不用你复述流程。

**Skill 和 MCP 可以分开装。** 只装 Skill 也行——它里面写了 HTTP 兜底路径，即使 MCP 没连上，agent 也能起服务、渲染、落盘，只是最后一步要你在浏览器里手动复制。

## 排错

**客户端里看不到工具 / 服务起不来**

先手工跑一遍，看是不是启动本身就失败了：

```bash
/path/to/wechat-md-mcp/bin/md-mcp
```

正常的话会打印 `[wechat-md-mcp] MCP server running on stdio` 然后等你输入，Ctrl-C 退出。没打印出来，说明错误在启动阶段。

**`[wechat-md-mcp] dependencies missing`**

`node_modules` 没装。在仓库目录跑一次 `npm install`。

**`[wechat-md-mcp] no Node >= 20 found`**

这通常发生在 Claude Desktop、Codex 这类 GUI 客户端里——它们不会继承你 shell 的 PATH，所以找不到 node。

启动器会依次尝试 `$MD_SERVICE_NODE`、PATH、以及几个常见绝对路径（Homebrew、Node 官方安装包、nvm、fnm、volta）。如果你的 node 装在这些之外，显式指定最稳：

```bash
export MD_SERVICE_NODE=/你的/node/路径
```

要把这个变量传进 GUI 客户端，在配置里用 `env` 块：

```json
{
  "mcpServers": {
    "wechat-md-mcp": {
      "command": "/path/to/wechat-md-mcp/bin/md-mcp",
      "args": [],
      "env": { "MD_SERVICE_NODE": "/你的/node/路径" }
    }
  }
}
```

Codex 的写法是独立的 `[mcp_servers.wechat-md-mcp.env]` 段。

**工具调用能过，但加工出来的 HTML 在微信里没样式**

确认没有把 `inline` 设成 `false`。微信会剥掉 `<style>` 标签和 class，不内联就等于白排。详见 README 的注意事项。
